You're asking a great question. It gets to the heart of how shell scripting languages handle data.

You are correct that gdate outputs strings. However, the printf command on the next line uses the format specifier %02d.

  • %s would mean "insert this as a string".
  • %d means "interpret this as a decimal integer and format it".

The 02 part of %02d adds a specific formatting rule: "pad with a leading zero to a width of two characters". This is what ensures that 7 becomes 07.

Because the command uses %d, bash is forced to interpret "08" and "09" as numbers before formatting them. The problem is that, by default, shells interpret numbers with a leading zero as octal (base-8). Since 8 and 9 are not valid octal digits, it fails.

So, while gdate provides a string, the *formatting requirements* of printf force a numeric interpretation, which is why we need to explicitly tell it to use base-10.
